# ADR-030 — Embedding ของ KB ด้วยโมเดลที่รันในเครื่อง (Ollama + โมเดล multilingual) เพื่อให้ semantic search ใช้ได้จริง

- **Status:** Accepted 2026-11-06 — independent re-review T-432-rereview.md ไม่พบ P1/P2 ค้าง; การเปิดโมเดลจริงยังเป็น T-433 พร้อม caveats
- **Date:** 2026-11-05 (เวลากรุงเทพ) · **ผู้ตัดสิน:** เจ้าของ (เลือกทาง ก. รันโมเดลเอง + อนุมัติดาวน์โหลดโมเดลหนึ่งครั้ง `[CONFIRMED 2026-11-05]`) + main thread (รายละเอียด) · ผ่าน `security-reviewer` (N7) ตรวจซ้ำ 2026-11-06; ไม่ถือว่า real-image/คุณภาพโมเดลผ่านแล้ว
- **Context:**
  - KB ค้นแบบ hybrid อยู่แล้ว (`packages/domain/src/kb/search.ts`: keyword + vector ผ่าน pgvector รวมด้วย RRF, chunk + `kb_embedding_index` ที่ active ได้ทีละ index, migration 0019) `[TESTED: อ่านโค้ด 2026-11-05]`
  - provider ของ embedding มีแค่ `mock` (vector ปลอม ไม่สื่อความหมาย) และ `vertex` (`EMBEDDING_PROVIDERS` ใน `packages/shared/src/config.ts`) · POC ใช้ `claude -p` ซึ่งไม่มี embedding (Anthropic ไม่มี embedding API) → semantic search บน POC ใช้ไม่ได้จริง เหลือแต่ keyword `[ยังไม่ยืนยัน 80%: ยังไม่ได้ดูค่า env ของ POC]`
  - เจ้าของต้องการให้ KB (จาก folder `WATCHTOWER_KB_DIR` / `pnpm kb:sync`) ค้นเชิงความหมายได้ ภาษาไทยและอังกฤษ · Jarvis (ADR-029) ใช้ `kb_search` / `kb_get`

## Decision
1. **Service ใหม่ `embedder` ใน docker compose (profile `ai`)** ใช้ image ทางการของ Ollama (pin tag + digest ที่ตรวจจาก Docker Hub/เอกสารทางการ ณ วันที่ implement แล้วบันทึกวันที่/ลิงก์ใน ADR นี้) · อยู่บน network `embed` เท่านั้น ซึ่งเป็น `internal: true` (ไม่มี route ออก internet) และมีสมาชิกแค่ embedder + api + worker (web/caddy/minio/claude-bridge เข้าไม่ได้ — Ollama API ไม่มี auth และมี endpoint จัดการ `/api/pull|push|create|delete` จึงต้องจำกัดผู้เข้าถึง; แก้ตาม T-432 C-2) · **ไม่ publish port ออก host** · volume `embeddermodels` เก็บโมเดล · รันเป็น uid 1000, `read_only` + tmpfs `[ยังไม่ยืนยัน 60%: ยังไม่รันกับ image จริง]` · image pin tag + digest เท่านั้น ไม่มี env override (T-432 C-6)
2. **โมเดล:** `bge-m3` (multilingual รวมไทย, 1024 มิติ, ~1.2 GB) เป็นค่าเริ่มต้น `[ASSUMED]` · ตัวเลือกสำรองที่เล็กกว่า `multilingual-e5` ตั้งผ่าน env `EMBEDDING_MODEL` · ไม่ hardcode ชื่อโมเดลในโค้ด (ค่าอยู่ใน env/`config/models.yaml`)
3. **ดาวน์โหลดโมเดลครั้งเดียว:** init container `embedder-init` รัน `ollama serve` ของตัวเอง (ฟังที่ loopback ในตัวมันเอง) บน network `embed-egress` (ออก internet ได้ ไม่มี service อื่นอยู่) แล้ว pull โมเดลลง volume ถ้ายังไม่มี จากนั้น chown ให้ uid 1000 และจบ (เหมือนแบบ `minio-init`) — **ตัว `embedder` ที่รันต่อเนื่องไม่เคย pull และไม่มี egress** (แก้ตาม T-432 C-2: เดิม init สั่ง pull ผ่าน server ของ `embedder` ทำให้ embedder มี egress ถาวร) · ปลายทางเดียวที่ออก internet คือ registry ของโมเดลตอน pull ของ `embedder-init` — บันทึกใน `docs/09-SECURITY.md` · pull ล้ม = embedder ไม่ healthy → search ถอยไป keyword อย่างเดียว (ทำงานแบบเดิม ไม่ใช่ mock)
4. **Provider `local` ใน `packages/ai`:** `EMBEDDING_PROVIDERS = ['mock','vertex','local']` · adapter เรียก HTTP endpoint embed ของ Ollama ที่ `EMBEDDING_LOCAL_URL` (default `http://embedder:11434`) ด้วย timeout + retry + เพดานขนาด batch · ผ่าน `createAuditedEmbedding` เดิม (audit ใน `ai_run`, cost = 0) · ข้อความผ่าน redaction ตามนโยบายเดิมของ embedding (ADR-008) · host allow-list: ยอมเฉพาะ loopback กับชื่อ service ที่ระบุตรงตัว (default `embedder`, เพิ่มได้ด้วย `EMBEDDING_LOCAL_HOSTS`) — ไม่ใช่ชื่อ single-label ใดก็ได้ (กัน `metadata`, `redis`, ชื่อ intranet; T-432 C-3) · อ่าน response เป็น stream และตัดที่ 8 MB (C-4) · **เพดาน token ของ embedding แยกจาก LLM** (`EMBEDDING_DAILY_TOKEN_CAP`, default 5M/วัน UTC `[ASSUMED]`): `ai_run` ของ agent `embedder` ไม่ถูกนับใน `AI_DAILY_TOKEN_CAP` และ guard ตัดสิน embedder ด้วยเพดาน embedding อย่างเดียว เพื่อไม่ให้ re-embed ทั้ง KB หยุด triage/draft/assistant (T-432 C-1)
5. **Index:** สร้าง `kb_embedding_index` ใหม่ `(provider 'local', model, dimensions)` แล้ว re-embed ทุก chunk ใน worker (job เดิมของ kb) · สลับ active เมื่อ embed ครบ (atomic) · **ระหว่างเติม index ใหม่ search ไม่ได้อ่าน index เก่าต่อสำหรับบทความที่ย้ายแล้ว:** chunk หนึ่งแถวเก็บ vector เดียว (`embedding_index_id`) บทความที่ embed ด้วย index ใหม่แล้วจึงหาได้แค่ด้วย keyword จนกว่าจะสลับ ส่วนบทความที่ยังไม่ถึงคิวยังมี vector เดิม (hybrid เต็มเฉพาะบทความเหล่านั้น) · re-embed ไม่ลบ chunk เดิมก่อนมี vector ใหม่ และหยุดทันทีเมื่อ guard ปฏิเสธ (เพดาน embedding/kill switch) โดย job ไม่ fail (ไม่ retry วน) รอบ 04:00 UTC ถัดไปทำต่อ (T-432 C-1, C-8) · `pnpm kb:sync` และการแก้บทความ embed ใหม่ตามปกติ · ไม่เปลี่ยน schema (vector ไม่จำกัดมิติอยู่แล้ว; trigger ตรวจมิติกับ index) → **มี migration 0114** (แก้ 2026-11-05 ตอน implement: CHECK ของ `provider` ใน `kb_embedding_index` และ `ai_run` ต้องรู้จัก `local`)
6. **Query embedding:** api embed คำค้นด้วย provider เดียวกัน (timeout สั้น เช่น 1.5 s) ล้ม/ช้า = keyword อย่างเดียว ไม่ทำให้ search ล้ม
7. **ค่าความใกล้เคียงขั้นต่ำ** (`KB_MIN_VECTOR_SIMILARITY`, ตอนนี้ 0.25 `[ASSUMED]`) ปรับด้วยชุดคำถาม TH/EN ของ KB ตัวอย่าง (`examples/`) และบันทึกค่าใน ADR นี้เมื่อวัดแล้ว
8. **ทรัพยากร:** CPU อย่างเดียวได้ (ไม่ต้องมี GPU) · ตั้ง memory limit ของ container · concurrency ของ embed จำกัดใน worker เพื่อไม่แย่ง CPU กับ service อื่น

## Options considered
- **ก. Ollama + bge-m3 ในเครื่อง (เลือก, เจ้าของ)** — ไม่มีค่าใช้จ่ายต่อครั้ง ข้อมูลไม่ออกนอกเครื่อง รองรับไทย / ดาวน์โหลดโมเดลครั้งแรก, ใช้ CPU/RAM
- ข. Vertex AI — มีโค้ดแล้ว / ต้องมี GCP key, ข้อมูลออกนอกเครื่อง
- ค. API แบบเสียเงิน (เช่น Voyage) — คุณภาพดี / มีค่าใช้จ่าย, ข้อมูลออกนอกเครื่อง
- Hugging Face text-embeddings-inference — เร็ว / image ใหญ่, จัดการโมเดลยุ่งกว่า Ollama สำหรับเครื่อง Windows + Docker Desktop
- โมเดลใน process ของ Node (transformers.js/onnx) — ไม่ต้องมี service เพิ่ม / โหลดโมเดลซ้ำทุก process (api + worker), กิน RAM ของ process หลัก

## Consequences
- งาน T-430 (`ai-engineer`/`integration-engineer`): service + init + provider `local` + test (contract test ด้วย fake HTTP, ไม่ต้องมีโมเดลจริงใน CI) · T-431 re-embed + สลับ index + ปรับ threshold ด้วยชุดคำถาม · T-432 `security-reviewer`
- CI ไม่ดาวน์โหลดโมเดล (ใช้ mock/fake) · e2e ที่ต้องใช้โมเดลจริงรันมือบนเครื่องเจ้าของ
- ตรวจซ้ำเมื่อ: คุณภาพภาษาไทยไม่พอ (ลองโมเดลอื่น), เครื่อง pilot RAM ไม่พอ, ย้ายไป GCP (อาจใช้ Vertex)
